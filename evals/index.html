The methodology in 6 bullets

  • 1. Use the tool first. Don't build evals before you have real data. Phase 1–2 = passive use + traces accumulate.
  • 2. Look at data weekly. 30–60 min/day ritual. Manually review 20–50 LLM outputs. Take open-coded notes, no categories yet.
  • 3. Cluster failures the next day. Re-read notes fresh. Same shape three times = a confirmed failure mode. Document as FM-NNN.md.
  • 4. Fix one mode carefully. Highest severity × frequency first. One change at a time. Don't ship without measuring.
  • 5. Measure on a frozen test set. If you iterated on it, it's dev. Test set is touched only at release decisions.
  • 6. Write up every change. Before/after numbers + statistical significance. That writeup becomes a portfolio artifact.
